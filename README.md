# OmniDash

**Панель управления серверами — без Docker, без GitHub и без облака.**
Один Node.js-процесс, JSON-база, живой интерфейс на SSE. Логин, выдача серверов, доступы, порты, лимиты, сроки, консоль, файлы, бэкапы, расписание, журнал и автообновление — всё своё, всё локально.

```
  ┌──────────────────────────── OmniDash ────────────────────────────┐
  │  обзор   серверы   узлы   аллокации   шаблоны   журнал   настройки │
  ├──────────┬───────────────────────────────────────────────────────┤
  │  ⌘K      │  Мир Друзей            ● running   0.0.0.0:25565       │
  │  обзор   │  Paper 1.21.4 · 3 ГБ · 250% CPU · до 26 ноября         │
  │  серверы │  ┌ консоль ─┬ управление ┬ файлы ┬ бэкапы ┬ доступы ┐  │
  │  люди    │  │ [Server] Done (2.6s)! For help, type "help"       │  │
  │  узлы    │  │ > say привет                                       │  │
  │  ...     │  └───────────┴────────────┴───────┴────────┴────────┘  │
  └──────────┴───────────────────────────────────────────────────────┘
```

> Это демонстрационное приложение с живыми процессами-эмуляторами. Панель реально запускает
> `node demo/minecraft-mock.js`, `node demo/bot-mock.js` и `python3 demo/python-bot.py`,
> собирает их stdout/stderr, CPU/RAM/диск, принимает команды и делает ZIP-бэкапы.

## Быстрый старт

Нужен только **Node.js ≥ 18.17**. Единственная runtime-зависимость — `ssh2` (SFTP-сервер); `start.bat`/`start.sh` ставят её автоматически при первом запуске (`npm install`).

```bash
node server.js          # или: npm start
# → http://localhost:7777
```

Первый запуск создаёт `data/` и наполняет её демо-данными: 6 серверов, 4 пользователя, 2 узла, 17 портов, 4 шаблона.

| Логин   | Пароль      | Роль        | Что видно                                                        |
|---------|-------------|-------------|------------------------------------------------------------------|
| `admin` | `omnidash`  | администратор | всё: люди, узлы, порты, шаблоны, журнал, настройки, обновления   |
| `steve` | `steve123`  | пользователь | 3 своих сервера, лимиты 8 ГБ / 300% / 40 ГБ, запрос продления    |
| `mira`  | `mira123`   | пользователь | 2 сервера, включая python-бота                                  |
| `kotik` | `kotik123`  | пользователь | сервер с истёкшим сроком — видно, как работает авто-приостановка |

**Что посмотреть за три минуты**

1. Войти админом → «Обзор»: карточки нагрузки, лента событий, блок «Требуют внимания».
2. «Серверы» → «Мир Друзей» → «Консоль» → запустить, ввести `say привет`, увидеть ответ в логе.
3. «Файлы» → открыть `server.properties` → поменять `motd` → сохранить.
4. «Бэкапы» → создать копию → скачать ZIP.
5. «Доступы» → выдать `mira` право «Консоль», выйти и войти под `mira`.
6. Админом: «Пользователи» → лимиты и блокировка; «Узлы» → порты; «Обновления» → проверка.
7. Нажать `⌘K` / `Ctrl+K` — палитра команд.

`npm run dev` перезапускает панель при изменении `server.js`, `core/` или `version.json` и автоматически перезагружает вкладки через SSE — это и есть «временное автообновление», пока идёт разработка.

## Что умеет

### Вход и люди
- Логин по логину/паролю, scrypt-хеши, сессии в HttpOnly-cookie, срок жизни настраивается.
- Демо-подсказка на экране входа отключается: `PATCH /api/settings {"showDemoCredentials": false}`.
- Роли `admin` / `user`, блокировка, сброс пароля, лимиты на пользователя.
- Регистрация закрыта по умолчанию; открывается галочкой в настройках.
- API-ключи (`od_…`) для скриптов и внешних интеграций.
- Ограничение попыток входа (по IP + логину), журнал действий.

### Серверы и доступы
- Админ создаёт сервер и выбирает владельца; пользователь — в пределах своих лимитов.
- Субпользователи с девятью отдельными правами: консоль, управление питанием, файлы, бэкапы, переменные, настройки, доступы, расписание, порты.
- Владелец и админ имеют полный набор; субпользователь — только выданное.
- Передача сервера другому пользователю, приостановка/возобновление.

### Порты, лимиты, сроки
- Аллокации на узле: диапазон портов, массовое создание, выдача основного и дополнительных портов.
- Лимиты RAM, диска, CPU и числа серверов/бэкапов/портов — на пользователя и на сервер.
- Срок аренды: дата окончания, продление админом, запрос продления пользователем, авто-приостановка просроченных.
- Валидация пересечений портов и занятости аллокаций.

### Работа с сервером
| Раздел | Что делает |
|---|---|
| Консоль | живой stdout/stderr с ANSI-цветами, история, отправка команд |
| Управление | CPU/RAM/диск/игроки/TPS, графики, старт/стоп/рестарт, убить процесс |
| Файлы | дерево, редактор, создание, переименование, загрузка/скачивание, ZIP-архив и распаковка |
| SFTP | подключение любым SFTP-клиентом (FileZilla, WinSCP, scp): логин/пароль от аккаунта панели, после входа — папки доступных серверов; порт и вкл/выкл в настройках панели (по умолчанию 2222) |
| Импорт ZIP | создание сервера из готового ZIP-архива: кнопка «Импорт ZIP» на странице серверов, архив распаковывается в каталог нового сервера |
| Бэкапы | создание ZIP, восстановление, скачивание, удаление, лимит на сервер |
| Переменные | env-переменные шаблона + собственные значения, `startup` с `{{PORT}}` |
| Доступы | выдача и отзыв прав субпользователям |
| Расписание | задачи `command`, `power_*`, `backup`; интервал, ежедневно, еженедельно, cron-подобное |
| Настройки | имя, описание, лимиты, порты, срок, автостарт, удаление |

### Админка
Пользователи, узлы, аллокации, шаблоны (eggs), журнал, обновления, настройки панели (имя, акцент, MOTD, регистрация, срок сессии, срок аренды, лимиты по умолчанию), системная сводка.

### Интерфейс
Чёрно-белая тема, квадратные карточки, плотный дашборд, моноширинные акценты, живые графики, `⌘K`-палитра, тосты, модалки, скелетоны, адаптив до телефона. Дизайн — чёрно-белые квадраты в стиле OmniPanel (см. `docs/DESIGN.md`).

## Чего здесь нет (границы приложения)

Честно, чтобы не было сюрпризов:

- **Нет Docker/контейнеров.** Процессы запускаются от имени пользователя ОС, под которым работает панель. Это удобно для доверенного окружения и демо, но не даёт контейнерной изоляции.
- **Нет распределённых узлов.** Узлы — логические: порты, лимиты и размещение. Демон работает на той же машине; удалённое исполнение не реализовано.
- **Нет SFTP и выделенных FTP-аккаунтов** — файлы через веб-интерфейс.
- **Нет OAuth/Discord/2FA**, биллинга, поддоменов и живой миграции.
- JSON-хранилище рассчитано на небольшую панель (десятки серверов, сотни пользователей), без кластеризации.
- Ядро (`core/`, `server.js`) обновляется с перезапуском процесса; фронтенд — на лету.

Эти границы не мешают «посмотреть функционал дашборда» и вести небольшую панель, но для публичного хостинга тысяч чужих серверов нужен контейнерный рантайм.

## Автообновление без GitHub

Канал обновлений — файл `updates/update.json` и ZIP рядом (или любой свой URL). Никаких релизов на GitHub, как и просили.

**Собрать пакет**

```bash
npm run update                                   # текущая версия
npm run update -- --notes "починили консоль"     # с описанием
npm run update -- --bump 1.0.1 --notes "…"       # поднять версию и собрать
```

Скрипт `tools/make-update.js` кладёт код (`server.js`, `core/`, `public/`, `demo/`, `tools/`, `docs/`, `version.json`, `package.json`) в `updates/omnidash-<версия>.zip`, считает sha256 и обновляет манифест.

**Применить**

1. Панель → «Обновления» → «Проверить обновления».
2. Появится версия и кнопка «Применить» (для пакетов из `updates/`).
3. Перед заменой создаётся ZIP-бэкап кода в `data/updates/`, `data/` и `updates/` не трогаются.
4. Интерфейс перезагружается сам (SSE `reload`); если менялось ядро — нужен перезапуск процесса.

**Свой сервер обновлений** — в настройках укажите `updateUrl` на любой хостинг с таким же JSON:

```json
{
  "version": "1.1.0",
  "channel": "stable",
  "notes": "что нового",
  "package": "https://example.com/omnidash-1.1.0.zip",
  "sha256": "…"
}
```

Локальный пакет можно и просто перетащить в зону «Загрузить обновление» — панель сама сделает бэкап и применит.

**Живое обновление при разработке.** `npm run dev` следит за `server.js`, `core/` и `version.json`: перезапускает процесс, поднимает `buildId`, а открытые вкладки получают событие `reload` и перерисовываются. Это тот самый «временный» механизм, чтобы смотреть функционал без ручных перезагрузок.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `7777` | порт панели |
| `HOST` | `0.0.0.0` | адрес прослушивания |
| `OMNIDASH_DATA` | `./data` | каталог базы, серверов, бэкапов, логов, снимков обновлений |
| `OMNIDASH_URL` | — | внешний адрес для ссылок |
| `OMNIDASH_QUIET` | — | не печатать баннер |
| `OMNIDASH_LOG` | `1` | `0` — отключить файловые логи демонов |

Настройки панели (имя, акцент, MOTD, регистрация, срок сессии, срок аренды, лимиты по умолчанию, `updateUrl`, канал) лежат в «Настройках» и в `data/db.json`.

### Данные

```
data/
├── db.json          # пользователи, серверы, узлы, аллокации, шаблоны, журнал, настройки
├── servers/<id>/    # рабочие каталоги серверов (файлы, конфиги, логи)
├── backups/<id>/    # ZIP-архивы бэкапов
├── logs/            # stdout/stderr процессов
└── updates/         # снимки кода перед обновлением
```

Для бэкапа панели достаточно скопировать `data/`. Сбросить демо: остановить панель, удалить `data/`, запустить снова.

## API

Формат ответа: `{ "ok": true, "data": … }` или `{ "ok": false, "error": "…", "code": "…" }`.
Авторизация — cookie сессии или `Authorization: Bearer od_…`.

```bash
# вход
curl -c jar -X POST localhost:7777/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"omnidash"}'

# список серверов
curl -b jar localhost:7777/api/servers

# запустить сервер и отправить команду
curl -b jar -X POST localhost:7777/api/servers/<id>/power \
  -H 'Content-Type: application/json' -d '{"action":"start"}'
curl -b jar -X POST localhost:7777/api/servers/<id>/command \
  -H 'Content-Type: application/json' -d '{"command":"say привет"}'

# создать пользователя с лимитами
curl -b jar -X POST localhost:7777/api/users \
  -H 'Content-Type: application/json' \
  -d '{"username":"nick","password":"nick12345","limits":{"servers":2,"memory":4096}}'

# живой поток (SSE)
curl -b jar -N localhost:7777/api/events
```

Полный список — `docs/API.md`. События SSE: `hello`, `log`, `state`, `stats`, `servers`, `notify`, `reload`, `shutdown`.

## Безопасность

- Смените демо-пароли и отключите демо-данные перед публикацией; регистрация по умолчанию закрыта.
- Скрыть подсказки демо-входа: `PATCH /api/settings {"showDemoCredentials": false}`.
- Ставьте панель за HTTPS-прокси: cookie сессии `HttpOnly`, `SameSite=Lax`.
- Панель запускает процессы от своего пользователя ОС — не работайте под `root`.
- Ограничьте доступ к `data/` (там хеши, логи, бэкапы) и к самому порту.
- Лимитер входа — базовая защита; для публичного интернета добавьте `fail2ban`/прокси.
- Обновления применяйте только из доверенного источника: манифест + sha256 + снимок кода.
